# 收录与淘汰规则

## 总原则

资源库的价值来自“拒绝”，不是来自数量。

> 宁可 0 推荐，也不要 1 条看起来专业但主题错配、事实冲突或来源不清的推荐。

## 值得进入候选池

至少命中一项：
- 直接解决 ERP 项目真实任务；
- 显著改善顾问使用 AI 工具的配置、效率、质量或成本；
- 是工具/Skill 入口不可缺的官方/原始资源；
- 是高质量 Skill、Agent、MCP、模板集合或工作流；
- 是 SAP/Oracle/ERP 场景少见且可复现的实践；
- 是真正具有筛选价值的资源合集。

进入候选池不代表值得推荐。

## 默认拒绝

- “AI 可以写文档/总结/翻译”等常识；
- 泛 AI 新闻、融资、模型八卦；
- 纯营销、引流、卖课；
- 只展示成品、不解释关键过程；
- 单个普通 Prompt；
- 转载洗稿且原始来源不明；
- 明显过期且无法验证仍有效；
- 搜索摘要/截图二手信息；
- 需要执行未知脚本才能判断价值的资源；
- 与当前 topic 只是邻近相关、但不直接解决目标任务；
- 资源类型不符合本次明确请求（例如 tool 冒充 skill）；
- 实际交付物与 expected_output 不一致（例如 BPM 配置教程冒充流程图绘制教程）；
- critical material claim 与当前官方/原始事实冲突；
- 用 custom extension / third-party wrapper 的能力证明 standard product 原生具备同一能力；
- 平台/edition/部署范围不一致却未说明或被错误外推；
- GitHub fork 未解析 upstream 就作为首推。

## 推荐最低核验

- canonical：至少确认原始性和当前有效性；volatile 需 current anchor。
- practical：必须 `content_checked`；涉及 material claims 时必须完成 claim verification。
- Gate 未全部通过：不得评分，不得推荐。

## 重复判断

视为重复：
- 同 canonical_url；
- 相同原文的转载/镜像；
- 同一作者相同教程的图文/视频版本且无明显互补；
- 步骤、目标、版本、受众高度重合。

可同时保留：
- 官方原始 + 实操教程；
- Skill 原始仓库 + 中文使用案例；
- Windows/macOS 或 SAP/Oracle 存在实质差异的教程。

## 推荐理由纪律

允许写：
- 支持的明确功能；
- 可编辑/可交付的输出；
- 当前维护状态；
- 已核验的版本/平台；
- 对目标任务的直接价值；
- 必要限制。

禁止无证据写：
- 最好 / 最强 / 唯一 / 最完整 / 最认真；
- “行业标杆”“必看”“闭眼入”；
- 原文没有明确支持的能力推断。

如果需要表达比较，写具体差异：

> “相比候选 B，多了 Windows 步骤和 2026 版本配置说明。”

不要写：

> “这是最完整的教程。”

## “不生产知识”边界

允许：标题、链接、标签、必要限制、20–60 字推荐理由、极短核验说明。

禁止：长篇改写、完整视频转写、拼接多篇内容后作为新教程、擅自发明替代原作者的 Prompt/Skill。
