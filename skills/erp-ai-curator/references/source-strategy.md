# Source Strategy — 怎么找

回答"从哪些角度、哪些来源发现候选"。

## 多角度关键词

同一个任务换几种说法搜索，不要反复用同一组关键词：

- **按动作**：生成、配置、画、调研、学习、迁移
- **按工具环境**：Claude Code、Codex CLI、WorkBuddy、通用 Agent
- **按产出物**：可编辑 `.drawio`、Mermaid、交互原型、配置片段、分析报告
- **按人群**：SAP 顾问、Oracle 实施、ERP 开发、FSSC

避免只搜"ERP + AI"这类泛词，它们通常只带回营销内容和盘点文章。

## 原始来源优先

优先顺序：

1. 原始 GitHub / Skill 仓库
2. 官方教程与产品文档
3. 作者本人发布的实操文章或视频
4. 有明确步骤和产出的中文教程
5. 高质量英文实操资源
6. 真实项目案例

转载站、聚合站、内容农场只作为**线索**，不当作可推荐对象；找到线索后顺藤摸瓜回到原始出处。

识别 GitHub fork 与 upstream：不要把 fork 当作原作者的独立成果。

## ERP 专属与通用可迁移并行

两条线同时搜：

- **ERP 专属**：SAP、Oracle、具体模块名、Fit-Gap、Fit-to-Standard、需求调研
- **通用可迁移**：Agent Skill、draw.io、原型工具、prompt framework、代码理解

判断标准不是"标题里有没有 ERP"，而是：

> 这个通用资源能否直接迁移到 ERP 顾问的真实任务？

反过来，也不要因为某资源出自 ERP 圈就默认它更有价值。

## 中文 / 英文取舍

- 中文优先是**同等质量下的 tie-breaker**，不是质量豁免
- 若中文侧只找到二手转载、营销稿或过时内容，果断转向英文
- 英文资源明显更强时推荐英文，但用中文说明：为什么值得看、重点看哪部分、使用限制是什么

## 何时停止

满足以下任一情况即可停止搜索：

- 已有 1–2 个明显强于其他候选的资源
- 继续搜索反复遇到的都是同一批转载或更弱的候选
- 高风险事实已经找到当前官方 / 原始来源佐证

出现以下情况应继续扩展：

- 候选之间明显冲突，无法判断谁当前有效
- 只有元数据，始终没找到可阅读的原始内容
- 覆盖明显不足（只找到一种类型、一种语言或一个来源）

**不设固定查询数或候选数。**
