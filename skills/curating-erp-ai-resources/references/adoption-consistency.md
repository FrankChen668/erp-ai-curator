# 采用一致性检查

只在以下情况读取：**已经识别出一个具体能力缺口，但准备输出“无需专门资源 / 继续普通 AI / 先低成本试验”时。**

目的不是强迫推荐工具，而是防止另一种偏差：已经看见真实瓶颈，却因为 General-AI-first 而把它忽略掉。

依次检查三件事：

1. **缺口是否真实可观察？**
   - 当前 AI/Agent 是否确实拿不到关键系统/仓库事实、无法稳定交付所需格式、无法承担确定性处理，或在重复规模下产生明显返工？
   - 如果只是“某工具功能更多”，不算能力缺口。

2. **是否存在直接解决该缺口的专门能力？**
   - 例如系统/仓库真实访问、专业可编辑格式、确定性校验、批量维护/差异更新、受控本地执行。
   - 不要用 ERP 场景标签替代能力匹配。

3. **收益是否值得采用成本？**
   - 同时考虑安装、学习、迁移、权限、数据外发、维护和治理成本。

据此校准：

- 缺口不成立 → **A**；
- 缺口成立，但专门能力尚不明确或成本明显过高 → **C**，并写清低成本试验与升级触发条件；
- 缺口成立，专门能力直接命中，且预期收益足以覆盖采用成本 → **B** 或条件化 B，只发现/核验 0–1 个主方案；
- 关键事实缺失且不同答案会改变 A/B/C → 显式写未知项或条件分支，不要用 `C` 代替“信息不足”。

最后问一句：

> **如果把 Specialized resource 写成 none，我能否明确解释：为什么这个已经观察到的能力缺口仍不值得采用任何专门能力？**

解释不成立，就重新判断，不要直接输出 none。
