# Practitioner / Creator Discovery

只在用户明确要“最佳实践、教程、别人怎么做、实战案例、值得学的资源”时读取，或当前采用判断明显依赖真实 practitioner 经验时读取。

目的：防止 Curator 退化成“搜几个官网 + 自己重写教程”。

## 1. 先判断用户到底在找什么

如果用户明确要找已有实践/教程/实战资源，**资源发现本身就是任务的一部分**，不受 A/B/C 是否需要新增 Tool/Skill 限制。

因此：

- A 可以是“无需新增 Tool/Skill，但这里有 1–3 个很值得学的现成实践/教程”；
- B 可以是“需要专门能力，并给最值得看的实操资源”；
- C 可以是“暂不值得重投入，但先学这一个低成本实践”。

不要把 `A = 不新增能力` 错写成 `A = 不需要搜索实践资源`。

## 2. Discovery query 要同时覆盖任务与人群

不要只搜宽词，例如“流程图最佳实践”。把查询拆成几组高信号组合：

```text
任务/交付物 × AI 技术/工具
角色 × 任务 × AI
行业/工作语境 × 任务 × AI
具体可编辑/系统能力 × 实战/教程/踩坑
```

中国泛 ERP / ToB / 产品/项目用户常见扩展词：

- ERP / SAP / Oracle / 实施顾问 / 项目经理 / 产品经理 / ToB / 企业信息化；
- AI / Agent / Claude Code / Codex / WorkBuddy / Gemini / DeepSeek；
- draw.io / Visio / BPMN / Mermaid / editable / Skill / MCP；
- 实战 / 教程 / 工作流 / 案例 / 复盘 / 踩坑 / 模板。

按实际任务组合，不做固定关键词配额。

## 3. 中文 practitioner 生态优先发现

当用户是中文语境、泛 ERP / ToB / 产品经理/顾问工作时，优先检查能提供真实操作证据的生态，例如：

- Bilibili；
- 微信公众号；
- 小红书；
- 知乎 / 人人都是产品经理 / 掘金 / CSDN / 独立博客；
- GitHub 上对应作者的 Skill / repo / examples。

这些平台负责回答“别人到底怎么做、输入什么、产出什么、哪里踩坑”。

官方/规范主要负责：

- 当前能力；
- 版本/兼容；
- 安装；
- 权限/隐私；
- 标准语义。

**用户问实践/教程时，official-only 不是合格完成。**如果最终没有 practitioner 资源，必须明确：

- 已尝试了哪些高信号 discovery 路径；
- 为什么候选没有通过；或
- 哪个平台存在 access / coverage gap。

## 4. 互动量只做 discovery prior

当平台公开可见时，可用互动信号帮助决定先看谁，但不能直接证明质量。

### Bilibili

优先看：

`收藏 + 投币 + 有效评论 > 播放/点赞 > 粉丝数`

### 小红书

优先看：

`收藏/收藏率 + 有效评论 > 点赞 > 粉丝数`

### 微信公众号

公开互动数据有限，优先：

- 持续原创实操；
- 具体截图/模板/案例；
- 同一主题长期积累；
- 被其他 practitioner 交叉引用。

真正进入推荐前仍必须检查具体内容是否有：

- 真实步骤；
- 真实输入/输出；
- 可复现做法；
- 失败/返工/限制；
- 与用户当前角色和交付物的匹配。

## 5. 输出必须先完成“选择”，再总结

用户明确要找实践/教程时，默认输出顺序：

1. **最值得看的 1–3 个实操资源** — 标题/作者/平台/链接；
2. **为什么值得看** — 每个资源只写真正的任务匹配和可学内容；
3. **优先级** — 如果只能看一个，看哪个；
4. **边界** — 谁不适合、哪里可能过时/营销化/只证明作者自实践；
5. **Curator synthesis** — 最后才总结共同做法。

不要先写 8–10 条自己的教程，再把几个官网当参考资料附在后面。

## 6. Candidate admission

一个资源优先保留，当它至少满足多数条件：

- 与用户角色/工作语境高度相关；
- 展示真实操作，而不是泛泛讲概念；
- 有具体输入 → 操作 → 输出；
- 结果是用户真正需要的 artifact（例如可编辑 draw.io / Visio / PPT / Word）；
- 有明显 failure/rework/限制信息；
- 当前仍可用；
- 相比其他候选增加新的决策信息。

高互动但营销标题、无可复现内容的资源应降级。

## 7. 平台访问不等于平台价值

普通 Web 能发现和读到时直接使用。

如果某个平台很可能包含 material practitioner evidence，但普通 Web 只能发现标题/摘要或无法读正文/字幕：

- 有已安装、已批准的 read-only source adapter 时，可按需调用；
- 没有时明确 `coverage gap`；
- 不要因为平台访问困难就改用官网并声称“最佳实践已完成”。

不要为了覆盖率自动调用所有平台，也不要为了当前一次搜索自动安装高权限第三方 adapter。

## 8. 最终失败检查

返回前问：

> **如果把我自己写的教程全部删掉，剩下的外部 practitioner 资源是否仍足够让用户知道“最值得看哪一个、为什么”？**

如果答案是否定的，而用户明确要的是最佳实践/教程，说明 curation 还没有完成。
