# Curation Case 003 — 多顾问周报/PPT 汇总与数据准确性检查

Date: 2026-08-30
Status: **REAL_USER_ORIGIN CURATION READY — NOT USER-USE EVIDENCE**
Produced with Skill: `curating-erp-ai-resources` `0.7.0`

> 来源：2026-08 训前调研中的真实实施顾问问题。原始痛点是“多个顾问各自编写周报 PPT，需要整合、汇总整体进度、检查和确认数据准确性，整理耗时长”。输入主要是 Excel / PPT，期望自动形成整合后的项目周报。

## 1. 真实问题

这不是单纯的“让 AI 合并 PPT”。

实际任务包含三层：

1. 从多个顾问材料中收集项目状态；
2. 汇总整体进度、风险、问题和本周/下周事项；
3. 保证关键数字、状态和口径可核对，再形成对外周报 PPT。

真正高风险点是：**如果源数据和口径没有统一，AI 可以生成一份形式完整但事实错误的周报。**

## 2. 当前 baseline

问卷显示当前主要靠人工整合；现成工作材料已经是 Excel + PPT。

对这个任务，普通企业 AI / 现有 Agent 已经能做：

- 摘要多份周报；
- 合并同类事项；
- 起草整体进度叙述；
- 根据模板生成 PPT 文案；
- 标记明显冲突或缺失项。

同时 Excel / 现有数据工具已经能承担：

- 总数/百分比/里程碑等确定性计算；
- 缺失、重复和口径一致性检查；
- 结构化状态汇总。

因此核心能力并不是“缺一个周报 AI Tool”。

## 3. Curator 0.7.0 结论

> **A — 当前不建议新增专门 Tool / Skill。优先改成“结构化事实源 + 确定性校验 + AI 叙事/PPT”工作方式。**

决定理由：

1. 输入、计算和输出都在现有 Excel/PPT/AI 能力范围内；
2. 最大风险是数据口径和 source-of-truth，而不是模型不会写周报；
3. 新增一个“周报 AI”不能自动解决源数据不一致；
4. 把确定性数字检查交给 Excel/脚本，把总结与叙事交给 AI，职责更清楚，也更容易复核。

因此本 Case 的外部专门资源推荐位为 **0**。

## 4. 当前更值得采用的实践

```text
顾问状态输入
→ 先进入统一结构化事实表/状态模板
→ 确定性检查缺失、重复、口径和关键数字
→ AI 只基于通过检查的事实源生成整体进度/风险/重点事项
→ 映射到固定 PPT 模板
→ PM 只复核异常项、关键数字和管理判断
```

关键原则：

- **数据事实与汇报叙事分层**；
- PPT 不是 source of truth；
- AI 不自行猜缺失数字；
- 计算逻辑优先确定性公式/脚本；
- AI 输出需要能回到原始顾问输入或事实表。

这不是需要新 Skill 的“最佳实践包”，而是对现有工具链的职责重新分工。

## 5. 为什么不推荐外部资源

0.7.0 允许 A 类结果不搜索、不凑资源。

当前已经能稳定回答采用决策：

> **先解决数据结构和事实校验，再让 AI 负责汇总表达。**

继续搜索“AI weekly report tool / PPT Skill / project report Agent”不会改变这个下一步，反而容易让用户把数据治理问题误认为模型能力问题。

## 6. 升级信号

只有出现以下可观察瓶颈时，再进入 B：

- 每周数据量/项目数很大，人工把顾问输入整理到统一事实表本身成为主要成本；
- 顾问数据来自多个系统/API，持续手工导入明显低效；
- 固定 PPT 生成和发布重复度很高，模板映射已稳定；
- 需要自动从 ALM/ERP/项目管理系统读取最新状态，而普通文件输入已经成为瓶颈；
- 企业已经有受控自动化平台，新增自动连接/生成的治理成本很低。

此时值得补的通常是**数据采集/模板自动化/系统连接能力**，而不是更强的聊天模型。

## 7. 给用户的最小 Curator 输出

> **这类周报目前不用急着找新的 AI Tool/Skill。先把多顾问输入统一成一张结构化事实表，用 Excel/确定性规则检查关键数字和状态，再让现有 AI 负责整体进度、风险和 PPT 文案。真正需要升级的信号，是“每周搬运/同步数据”本身已经成为主要成本；到那时再考虑自动连接项目系统或模板化生成。**

## 8. Evidence boundary

这是基于真实问卷问题、当前工具能力边界和此前 P06 对“确定性数据处理优先 plain code / deterministic baseline”的已接受方法证据形成的 A 类 Curator 判断。

它没有证明真实用户已经采用该方法，也没有证明实际节省了周报时间；这些仍属于 `REAL_USER_USE` 证据。
