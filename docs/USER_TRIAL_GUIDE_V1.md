# ERP AI Curator — Controlled User Trial Guide V1

Date: 2026-08-30
Status: **CONTROLLED TRIAL ENTRYPOINT**
Skill: `curating-erp-ai-resources` `0.7.0`

> 本文面向真实试用用户/管理员，不要求用户理解项目历史、P01–P07、Gate、Harness 或 validation 文档。

## 1. 这是什么

ERP AI Curator 用于回答一种问题：

> **“我这个真实 ERP / 企业信息化工作，当前 AI/Agent 已经够不够？如果不够，什么现成实践、Tool、Skill、MCP、方法或教程值得优先采用？”**

它不是：

- AI 工具大全；
- ERP 知识问答库；
- 自动替用户完成所有工作的 Agent；
- 必须推荐新工具的搜索器。

它可以合法回答：

- A — 你现有工具已经够，不要再装；
- B — 某个专门能力确实值得引入；
- C — 可能有价值，但当前先不要复杂化。

## 2. 谁适合试用

适合：

- SAP / Oracle / ERP 实施/业务顾问；
- 项目经理、产品经理、解决方案人员；
- ERP/企业系统开发、测试、数据、运维人员；
- 已经在使用 ChatGPT、Codex、WorkBuddy、Claude Code、Qoder 或其他 Agent，并开始遇到“应该怎么选 AI 工作方式”的人。

不适合把它当成：

- ERP 专业知识的最终权威；
- 生产系统自动修复工具；
- 无权限限制的系统访问 Agent。

## 3. 安装/导入

Skill 包目录：

`skills/curating-erp-ai-resources/`

必须整体保留：

```text
curating-erp-ai-resources/
├── SKILL.md
└── references/
    ├── adoption-consistency.md
    ├── decision-boundaries.md
    └── evidence-and-safety.md
```

### 支持 Agent Skills 的宿主

将整个目录按宿主产品的 Skill 导入/安装方式导入，不要只复制 `SKILL.md` 而丢掉 references。

OpenAI 当前 Skills 使用 `SKILL.md + resources` 的可分享结构，并可导入支持 Agent Skills 格式的产品，包括 Codex：

- https://academy.openai.com/public/clubs/work-users-ynjqu/resources/skills

本项目内部工程回归已经在 Codex 独立上下文中执行过旧版本 Skill，证明这种包结构在 Codex 路径可用；**这不等于 0.7.0 已在所有宿主上完成兼容性验证。**

如果目标宿主不支持 Agent Skills，或无法让 Skill 访问 references / Web，则不能假装完整兼容。

## 4. 用户怎么问

不需要特殊模板，也不要告诉用户先选 A/B/C。

直接说真实问题即可，例如：

- “我们每周要合并很多顾问周报，这个事情怎么用 AI 更合适？有没有必要装专门工具？”
- “我要维护几十份 ERP 操作手册，有没有别人已经跑通的 AI 做法？”
- “Oracle EBS 二开现在用什么 AI 工作方式更合理？”
- “SAP 程序报错，我已经有 dump 和代码，是否值得接 MCP/Joule？”
- “我们已经有 Codex/WorkBuddy，这个原型工作还值得再装 Skill 吗？”

用户最好自然提供会改变判断的事实：

- 当前已经在用什么 AI / Agent / 内部工具；
- 手头有哪些真实材料；
- 最终要交付什么；
- 数据/源码能否离开环境；
- 是否需要特定格式/系统访问/权限；
- 任务是偶发还是高频重复。

缺少这些信息时，Skill 应明确条件/未知项，而不是自动判 C。

## 5. 用户应该得到什么

一个合格回答应该让用户很快知道：

1. **当前工具链够不够；**
2. 如果不够，真正缺的能力是什么；
3. 当前任务下最值得优先借鉴的实践；
4. 默认 0–1 个最值得看的外部资源；
5. 什么条件下不要采用；
6. 从哪里开始。

用户不需要收到：

- 十几个工具；
- 统一打分表；
- 为了项目验证而设计的测试协议；
- 没有证据却声称“全球最佳”的结论。

## 6. Web / 外部资源边界

完整的 B 类 curation 通常需要宿主具备可用的 Web/search/fetch 能力。

如果宿主没有网络能力：

- 仍可基于用户材料做 A/B/C 初步判断；
- 可以分析用户已经提供的资源；
- 但不得冒充已完成当前互联网最佳实践搜索；
- 应明确 `coverage gap`。

## 7. 企业安全边界

- 不上传组织不允许外发的客户数据、源码、凭据、日志或截图；
- 诊断/理解默认 read-only；
- Tool/MCP 能写入不代表当前任务应该给写权限；
- AI 输出是待复核建议，不是 ERP 系统事实；
- 版本、权限、隐私、兼容、价格等当前事实需要当前来源核验。

## 8. 试用期间不要求用户做什么

用户**不是项目测试员**。

不要要求用户：

- 跑固定 10 题；
- 比较多个 AI 版本；
- 按项目设计的工具实验步骤回报；
- 给复杂评分。

用户正常使用即可。

如果自然产生反馈，只记录：

- 这个建议有用/没用/错在哪里；
- 是否让你少搜了东西或少选错工具；
- 是否漏掉了真实环境/权限/版本约束；
- 你采用、修改、拒绝还是忽略，为什么；
- 是否愿意下次再把类似问题交给 Curator。

## 9. 当前发布边界

当前版本可以做：

> **小范围、受控真实用户试用。**

当前不能宣称：

- 已验证成熟产品；
- 比普通 AI/自己搜索稳定更好；
- 已证明节省多少时间；
- 企业统一标准；
- 所有 Agent/平台都兼容。

这些只能由真实用户使用和兼容性反馈继续验证。

## 10. 管理员/项目 Owner 的停止规则

如果真实用户没有暴露明确缺陷，不要继续在内部增加规则、Gate、测试题或场景库。

只有以下真实信号才触发下一版：

- Skill 经常不触发或误触发；
- 明显 over-tooling / under-tooling；
- 证据角色反复标错；
- 漏掉数据/权限/版本边界；
- 用户看完仍不知道怎么选；
- 某宿主反复出现安装/reference/Web 兼容问题。
