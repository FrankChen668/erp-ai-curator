# Product Vision — ERP AI Curator

## 1. 一句话定义

> **给定一个 ERP 项目中的真实工作任务，ERP AI Curator 从互联网中筛出 0–2 个当前最值得继续投入时间的原始资源，并说明为什么值得看。**

它的价值不是“找到更多”，而是**替用户减少搜索、阅读和判断成本**。

## 2. 两类用户必须分开

### 2.1 Skill 操作者

直接调用 Skill 的人或 Agent，例如：

- 内部 AI 培训/资源负责人；
- ERP 顾问团队中的知识运营者；
- 本地 Agent；
- 想为某个任务快速做资源筛选的顾问本人。

操作者关心的是：

> 我给一个真实主题，你能不能替我找到并筛掉大部分噪声？

### 2.2 最终受益者

真正点击资源的人，例如：

- SAP / Oracle 实施顾问；
- 项目经理；
- 产品/业务顾问；
- ERP 开发人员。

最终受益者关心的是：

> 这个链接能不能让我更快学会、配置、理解或完成当前工作？

**产品优先优化最终受益者的点击价值，而不是操作者看到的流程完整度。**

## 3. 核心 Job To Be Done

当 ERP 项目人员遇到以下情况：

- 想用 AI 画流程图、原型、架构图；
- 想找到某个实用 Skill / Tool；
- 想配置 Claude Code / Codex / 本地 Agent；
- 想用 AI 改善需求调研、Fit-Gap、方案设计；
- 想快速理解一个陌生 SAP / Oracle 模块；
- 想找一篇真正有步骤、有结果的实操文章或视频；

他们通常面对的问题不是“没有搜索结果”，而是：

- 搜索结果太多；
- 标题党、转载、营销内容多；
- 很难判断是否适合自己的任务；
- 很难判断是否过时；
- 中文资源方便，但质量参差；
- 官方资料可靠但经常不够实操；
- 热度高不代表适合 ERP 顾问。

ERP AI Curator 要完成的是：

> **把高噪声搜索结果压缩成一个可以直接做决定的小集合。**

## 4. 产品不是“搜索”，而是“选择”

普通搜索解决的是 Recall：

> 有哪些相关结果？

ERP AI Curator 解决的是 Decision：

> 哪一两个最值得我现在点开？

因此产品必须承担四个动作：

1. **理解任务**：用户实际要完成什么，不只看关键词；
2. **发现候选**：从多个来源找出不同类型的候选；
3. **横向比较**：比较任务适配、实操价值、时效、来源与限制；
4. **做出取舍**：最多保留极少数，并允许 0 推荐。

只完成前两步，不构成产品价值。

## 5. 核心设计原则

### P1 — 强匹配比覆盖更重要

默认少而精。

弱匹配、只是“相关”、需要大量解释才能说明为什么有用的资源，不应进入推荐。

### P2 — 0 推荐是合法结果

找不到值得分享的内容时，明确说没有找到，不用凑数。

但“总是 0 推荐”同样是失败，因此后续 Eval 必须同时考察推荐质量与有效解决率。

### P3 — 资源类型是描述，不是先验牢笼

默认不要求用户先选 Tool / Skill / Tutorial / Case。

如果用户只是说“帮我找 AI 做原型的好资源”，不同类型可以竞争。

只有当用户明确限定“只找 Skill”或“只找中文教程”时，资源类型才成为硬约束。

这样避免 V0.4 中为了类型白名单而错失更好的结果。

### P4 — 中文优先是 tie-breaker，不是质量豁免

优先中文，前提是中文候选已经足够实操、可信、不过时。

如果英文资源明显更强，应推荐英文资源，并用中文说明：

- 为什么值得看；
- 重点看哪部分；
- 使用限制是什么。

不为了“中文优先”保留明显较差内容。

### P5 — 官方资料不是天然推荐位

官方资料有两种角色：

1. **用户资源**：本身就能帮助用户完成任务，可以推荐；
2. **事实锚点**：只是用于核验第三方说法，不一定展示给最终用户。

不能因为“官方”就占一个推荐位。

### P6 — 核验强度与风险成比例

普通方法、案例、设计实践主要判断：

- 是否直接解决任务；
- 是否有真实步骤/结果；
- 是否明显优于其他候选；
- 是否有迁移价值。

以下内容才升级为强事实核验：

- 安装与配置；
- API / Endpoint / 环境变量；
- 模型兼容；
- 价格；
- 产品版本；
- 标准产品是否原生具备某能力。

**不是所有文章都做 Claim Audit。**

### P7 — 保存与维护不是第一阶段核心

首次证明产品价值时，允许完全依赖运行时搜索。

资源数据库、CSV、Refresh、自动维护只有在真实使用证明“重复搜索成本已经成为主要问题”后才进入产品主线。

## 6. 产品的独特价值假设

ERP AI Curator 是否值得成为一个 Skill，而不是一条普通 Prompt，取决于它能否稳定提供以下增益：

- 更准确理解 ERP 工作任务；
- 更主动做多源搜索和横向竞争；
- 更少给“看起来相关但没用”的结果；
- 更敢于保持空缺；
- 对高时效配置类内容主动查官方；
- 输出稳定、简洁、可直接分享。

**这是可证伪假设，不是既定事实。**

如果 Phase 5 证明普通 Prompt 与 Skill 的结果没有显著差异，则应缩小甚至取消该 Skill，而不是继续增加复杂度。

## 7. 北极星结果

一次成功运行的最终感觉应该是：

> “我原本可能要搜半小时，现在这两个链接我愿意直接发给同事。”

不是：

> “这个 Agent 建立了很完整的候选 JSON 和验证记录。”
