# Survey Bridge — AI 培训问卷 → ERP AI Curator

Date: 2026-08-29

## 1. 为什么不重新设计问卷

现有《AI培训需求与实战问题调研问卷》已经具备我们需要的真实问题入口：

- 岗位；
- 当前 AI / Agent 使用情况；
- 最希望解决的 3 个实际工作问题；
- 从中选择 1 个重点问题补充场景；
- 当前处理方式与困难；
- 输入材料；
- 期望 AI 输出；
- 是否可提供脱敏附件。

因此 ERP AI Curator 不再另造一套需求表单。

## 2. 关键边界：培训问卷 ≠ Curator 问卷

培训问卷覆盖的是：

> “AI 可以如何帮助我的工作？”

ERP AI Curator 只覆盖其中一个子集：

> “为了完成这个工作，我需要选择什么外部 Skill / Tool / 教程 / 方法？”

所以**不能把所有问卷问题都丢进 Curator 搜资源。**

例如：

- “每周汇总多个顾问工作形成周报” → 优先直接解决 / 设计工作流，Curator 默认退出；
- “会议纪要整理需求清单” → 优先直接处理真实材料，Curator 默认退出；
- “接手陌生代码项目，希望快速理解结构” → 若用户只要结果，可直接分析；若在找长期工具 / Skill，Curator 才进入；
- “有没有能自动把代码库画成架构图的 Skill？” → Curator 进入。

这一步 triage 是项目边界，不是额外问卷负担。

## 3. 现有问卷字段如何映射

| 问卷内容 | Curator 用途 |
|---|---|
| 岗位 | `Role` |
| 第17题：最希望解决的 3 个实际问题 | 每个问题分别形成一个 `REAL_USER` task，保留原文 |
| 第18题①：发生场景 | task context |
| 第18题②：当前处理方式 / 最大困难 | current workaround / pain |
| 第18题③：输入材料 | context / attachment type |
| 第18题④：期望 AI 输出 | desired outcome |
| 第18题⑤：可否提供脱敏真实材料 | evidence / future training case availability |
| 附件 | task evidence；不自动进入公开仓库 |

多选题（AI 使用频率、工具、阶段、障碍、希望培训内容）用于**需求分布和培训设计**，但不应单独生成 Curator task。

## 4. 导入规则

### Q17 — 一条回答可以生成 0–3 个真实任务

每个“问题1/2/3”独立保存，不先合并。

例如：

```text
REAL_USER-001
Role: 项目经理
Original problem: 每周需要汇总多个顾问的工作内容形成项目周报，整理比较耗时。
```

先保留原文，再做 triage。

### Q18 — 丰富被选中的一个任务

如果填报人从 Q17 选择问题2做详细说明，Q18 信息附加到该 task，不另造一个重复 task。

### Attachment — 不复制敏感内容

问卷附件只保存引用 / 安全位置 / 脱敏状态。未经明确允许，不复制客户敏感文档进入公开仓库。

## 5. Triage 结果

每个真实 task 只增加一个轻量判断：

```text
Need external resource? yes / no / uncertain
```

### yes

用户核心决策是“找什么值得用”。进入 Curator。

### no

用户需要直接分析 / 写作 / 编码 / 制图 / 总结 / 研究。退出 Curator，但该问题仍然属于 AI 培训真实案例池。

### uncertain

例如“我想长期自动整理项目会议和行动项”。

如果只是处理这一次会议 → no。  
如果是在选长期工作方式 / Agent / Tool → yes。

必要时在实际培训或访谈中再问一句，不为了填字段阻塞问卷。

## 6. 为什么保留 no 很重要

如果只保存 `yes`，未来会误以为所有真实问题都需要资源推荐，从而把 Curator 做成万能搜索层。

`no` 样本能验证未来 Skill 的 trigger：

> 能不能在不该出现的时候安静退出？

因此 `no` 不是无用数据，而是产品证据。

## 7. 聚类方式

当回答积累后，可以按真实工作目标聚类，例如：

- 需求调研 / 需求沉淀；
- 原型 / 可视化；
- 项目计划 / 周报 / 会议；
- 测试 / Bug；
- 陌生模块学习；
- Coding Agent / 代码库理解；
- 培训 / 操作手册。

但：

- 原始问题永远保留；
- 聚类名称不是新的用户问题；
- 不因为某个分类没有回答就人工补题。

## 8. 真正的验证闭环

```text
问卷真实问题
→ 保存原文
→ triage 是否需要外部资源
→ yes: 云端 Curator 搜索 / 阅读 / 比较 / 0–2 推荐
→ no: 回到培训案例池，由对应 AI 方法直接解决
→ 记录“值得分享 / 一般 / 不值得分享”
→ 有条件时记录点击 / 尝试 / 转发 / 后续使用
```

## 9. 当前证据状态

当前云端能找到的是**问卷设计稿**，尚未发现实际填报结果数据。

因此目前可以完成：

- 问卷与 Curator 的接口设计；
- task intake 规则；
- OWNER_REAL 验证；
- discovery / Starter Pack。

但不能伪造 `REAL_USER` 结果。

一旦真实问卷结果进入可访问文件，优先级应立即高于继续扩充资源库。
